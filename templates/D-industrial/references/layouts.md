# 骨架库（layouts.md）· D · 工业技术风

16 个骨架，编号 D00–D15。**每个对开只用一个骨架**；内容多就拆成多个对开，不要往一个对开里塞。

容量是经验值：超出先删内容或拆页，不压字号硬塞。

---

## D00 / D01 · 封面（自动生成，勿手写）

左右两页合成一个对开。由 `meta` 驱动：左页放 logo、文档编号、公司名与定位语；右页放主标题、副标、大年份、关键指标带。

| 字段 | 说明 |
|---|---|
| `meta.cover.kind` | 文档类型标签（如「产品目录」） |
| `meta.cover.title` | 主标题，`\n` 断行 |
| `meta.cover.sub` | 副标，一句说清范围 |
| `meta.cover.stats` | 3–4 个关键指标，`{v, label}` |
| `meta.company` / `meta.org_line` | 左页公司名与定位语 |

纪律：主标题不超过 2 行；stats 不超过 4 个；不放大段文字。

## D02 · 目录（自动生成，勿手写）

由 `sections[]` 自动生成，双栏，带章节号与起始页码。右侧页留白——**这是有意的**，目录页不塞内容。

## D03 · 章节 opener（自动生成）

左页：章节号 + 标题 + 一句导语。右页：大章节号 + 英文标题 + 本章内容导览（`section.guide`）。

纪律：导语一句说完，不超两行；`guide` 不超过 6 条。

## D04 · 双栏/三栏正文

块 `text`，`cols: 2 | 3`。

| 字段 | 说明 |
|---|---|
| `paras[]` | 段落，每段 3–6 行；可写 `{zh, en}` |
| `pull` | 可选引文块 `{q, who}` |

容量：双栏 8–14 段；三栏 10–16 段。超出就拆到下一个对开。

## D05 · 牌号卡网格

块 `grades`，`cols: 2 | 3`。Catalog 主力骨架。

```jsonc
{ "type": "grades", "cols": 3, "cards": [
  { "code": "H13", "code_en": "AISI H13 / 1.2344",
    "name": { "zh": "热作模具钢", "en": "Hot-work tool steel" },
    "rows": [ ["标准", "ASTM A681"], ["硬度", "40–52 HRC"] ],
    "badges": ["ESR", "UT", "MTC"] }
]}
```

容量：3 列时一页 6 张（2 行 × 3 列）；2 列时 4 张。每张卡 `rows` 不超过 5 行，`badges` 不超过 3 个。

## D06 · 全宽规格表

块 `table`，默认 `side: "both"` 跨对开——**大表连续排两页，中缝有折号线**。这是 Catalog 与 TechData 的主力。

```jsonc
{ "type": "table", "title": {…}, "tables": [
  { "caption": { "zh": "供货范围", "en": "Supply Range" },
    "cols": [ { "k": "牌号", "en": "Grade" }, { "k": "直径", "en": "Ø", "num": true } ],
    "rows": [ ["H13", "20–350 mm"] ], "compact": true }
], "note": {…} }
```

- `cols[].num: true` → 右对齐 + 等宽数字。
- `compact: true` → 行高压缩，适合多行数据表。
- 容量：跨对开约 8–12 列 × 6–9 行。列数再多就拆表或删列。

## D07 · 化学-力学双表

块 `twin`，左右并排两张表。`wideLeft: true` 时左表宽（适合化学成分表列多）。

容量：每张表 4–7 列 × 5–8 行。

## D08 · 工艺流程

块 `flow`，`dir: "h"`（横向步骤带）或 `"v"`（纵向步骤列表）。

- 横向：4–8 步，每步标题一行 + 说明 2 行。
- 纵向：4–6 步，每步标题 + 说明 2–3 行（适合热处理窗口这类有细节的流程）。

## D09 · 图表对

块 `chart`，三个子组件可组合：

| 子组件 | 字段 | 纪律 |
|---|---|---|
| 数据条 | `bars:{max, rows:[{label,v,val}]}` | `max` 取数据最大值；每行必须有 `val` 文本标签 |
| 圆环 | `donut:{max,v,label,legend:[{k,v,s}]}` | 只表达一个占比；`legend` 2–3 项 |
| 数字 | `nums:[{v,label}]` | 2–4 个，配大字 |

容量：数据条 3–6 行。图表长度**全部由 `--v/--max` 计算**，不手写宽度。

## D10 · 全出血大图

块 `image`，`mode: "full"`。图铺满整个对开，图注压在左下。

纪律：图必须 ≥ 300dpi；图注不超过两行；一个文档最多 2–3 张全出血图，多了廉价。

## D11 · 数字带

块 `stats`，`cols: 3 | 4 | 5`。KPI 一字排开，上下粗线夹住。

容量：3–5 个数字。每个数字一行标签 + 一行英文。数字用等宽字体，不写单位在数字里。

## D12 · 认证网格

块 `certs`，4 列方格，每格一个认证代码 + 名称。容量 4–12 个。

## D13 · 时间线

块 `timeline`，`events:[{yr, title, desc}]`。容量 4–7 个事件；事件超过 7 个拆成两个对开或改为表格。

## D14 · 联系页

块 `contact`，双栏（商务联系 / 地址）+ 署名区。文档结尾用，通常前接一个 D15 幕封。

## D15 · 幕封/分隔

由 `dividers[]` 自动生成。用于章节之间的呼吸，或文档结尾的联系页引导。

---

## 通用容量铁律

- 一个对开一个主体。两个主体 = 两个对开。
- 任何骨架超出容量：**先删内容，再拆页，最后才考虑换骨架**。压字号是最后手段，且不许低于 `--fs-small`（8pt）。
- 页脚由脚本自动生成（`P.NN`），封面不编页；不要手写页码。
