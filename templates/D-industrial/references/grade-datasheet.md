# 牌号技术数据骨架（Grade Datasheet）

单牌号技术数据表（TDS / Technical Data Sheet）的内容规范。**不是**公司介绍、不是产品目录——那两类走 `profile` / `catalog`。

判定：读者拿这份文件要做三件事之一——**选材、定工艺、验收**。三件都做不到，就不该叫 Technical Data。

---

## 为什么需要一套固定骨架

同一份 TDS 有四种读者，问的是一件事的不同侧面：

| 读者 | 只关心 | 对应层 |
|---|---|---|
| 设计 / 选材 | 这个材料能做到多少、能不能替代 | L1 L3 |
| 工艺 / 热处理 | 怎么淬、怎么回、超温会怎样 | L4 |
| 采购 / 贸易 | 有没有货、什么规格、对标什么牌号 | L2 L5 |
| 质量 / 审厂 | 数据是谁给的、是典型值还是保证值 | L6 |

旧式做法是把这些内容按"有什么写什么"平铺，读者自己拼。骨架的作用是让每一层都能被单独翻到，且层与层之间不打架。

---

## 七层

### L0 标识层｜这是什么

```jsonc
"meta": {
  "doc": "techdata",
  "doc_no": "SS-TD-S7-2026",
  "year": "2026",
  "title": { "zh": "S7 工具钢 · 抗冲击钢", "en": "S7 Tool Steel · Shock-Resisting" },
  // 版本与基准日写进页脚：每一页都看得到，比只在封面写一次有用
  "footer": "SONGSHUN STEEL · SS-TD-S7-2026 · Rev V1.0 · 2026-10",
  "cover": {
    "kind":  { "zh": "技术数据", "en": "Technical Data" },
    "title": { "zh": "S7 工具钢\n抗冲击钢", "en": "S7 Tool Steel\nShock-Resisting" },
    "sub":   { "zh": "UNS T41907 · 1.2355 · 50CrMoV13-15", "en": "UNS T41907 · 1.2355" },
    "stats": [
      { "v": "ASTM A681", "label": { "zh": "标准依据", "en": "Standard" } },
      { "v": "S 组",      "label": { "zh": "AISI 归类", "en": "AISI group" } }
    ]
  }
}
```

四套编号（商品牌号 / 标准牌号 / UNS / 材料号）并列，客户来自不同体系，少一个就要多一轮邮件——封面 `sub` 或 `stats` 是最省地方的载体。标准号**必须带版本年**（`A681-08(2015)`），只写 `A681` 无法判断依据的是哪一版。

族别在 L1 的开头用一句说清"归到这一组的理由"，不要只写组名。

### L1 定位层｜为什么选它

- **一句话定义**：形态 + 核心能力 + 典型场景，≤40 字。
- **与同族的分界**：S 组有 S1/S2/S5/S6/S7，只列族名不对比，读者无法判断何时该换牌号。
- **成分设计逻辑**：每个关键元素一句话。Cr 给淬透性与耐磨、Mo 抗回火软化、Si 提回火抗力并减小变形、V 控晶粒。
- **典型应用**：带工况，不写"塑料模"，写"厚壁注塑模、受冲击冷冲模、热剪切刀"。
- **不适用场景**：反向界定比正向列举更能建立信任。

旧版常犯的错：整段写的是**族介绍**（S 组怎么分类、Si 有什么用），没有一句讲 S7 自己。族背景 ≤3 句，牌号自身定位 ≥3 句。

### L2 成分层

```jsonc
{ "type": "table", "tables": [{
  "caption": { "zh": "化学成分（wt%）", "en": "Chemical composition" },
  "basis": "spec",                    // 这里是标准要求，不是实测
  "cols": [
    { "k": "元素", "en": "Element" },
    { "k": "C", "num": true }, { "k": "Si", "num": true }, { "k": "Mn", "num": true },
    { "k": "P ≤", "num": true }, { "k": "S ≤", "num": true },
    { "k": "Cr", "num": true }, { "k": "Mo", "num": true }, { "k": "V ≤", "num": true }
  ],
  "rows": [[{ "zh": "含量", "en": "Content" },
    "0.45–0.55", "0.20–1.00", "0.20–0.90", "0.030", "0.030",
    "3.00–3.50", "1.30–1.80", "0.35"]]
}] }
```

- 元素横排（一列一个元素）比竖排省一半高度，也符合钢材数据表的惯例。
- 有实测典型值时加一列 `typical`，并给该列 `"basis": "typical"`——同一张表里两种身份必须分开标。
- 残余元素与气体（O / N / H / Cu+Ni+Sn）是 P2，但轴承钢、模具钢客户会问。
- 等效牌号表必须有**差异注记**列。只给"等效"不给差异，是把判断风险推给客户。

### L3 性能层

**每一条数据都必须成组出现：数值 + 试验条件 + 数据身份。缺任一，这条数据不能用于选材。**

```jsonc
"meta": {
  "test_conditions": [
    { "id": "TC-A",
      "label": { "zh": "淬回火基准", "en": "H&T basis" },
      "items": ["Austenitised 941 °C", "Air cooled", "Tempered 1 h / 25 mm"] }
  ]
}
```

```jsonc
{ "caption": { "zh": "回火温度与硬度", "en": "Tempering response" },
  "basis": "typical", "cond": "TC-A",
  "cols": [ { "k": "回火温度", "en": "°F", "num": true },
            { "k": "°C", "num": true },
            { "k": "HRC 下限", "en": "min", "num": true },
            { "k": "HRC 上限", "en": "max", "num": true } ],
  "rows": [ [{ "zh": "淬火态", "en": "As hardened" }, "—", "59", "61"],
            ["300", "149", "57", "59"] ] }
```

要点：

- `cond` 指向 `meta.test_conditions` 里的 id。条件只写一处，**全篇同步**。旧式做法是每个表各写一句，同文两页就会一个写 941℃、一个写 940℃，一个写回火 1 h/in、一个写 2 h/in。
- `basis` 取值：`spec`（标准要求）/ `min` / `max` / `typical`（典型值）/ `range`。表级标一次，列级另有用处（同一张表既有标准范围又有典型值时）。
- 硬度–回火表**拆成 min / max 两列**，不要写 `59/61`。斜杠含义不明——是上下限、还是两次试验？读者无从判断。
- 冲击功必须带**试验温度与试样尺寸**。只写"V-notch"不够：室温与 −20℃ 是两个材料。
- 尺寸变化要给**数值表**，不能只有曲线。模具设计要的是 mm/100mm。
- 淬透性（端淬 / 临界直径）是 S 系、H 系钢的必答题——开篇论证"靠成分控制淬透性"，就要给证据。

子块清单与优先级：

| 子块 | 内容 | 级别 |
|---|---|---|
| 物理 | 密度、弹性模量、泊松比（弹性常数归物理，不归强度） | P0 |
| 物理 | 电阻率、比热、热扩散 | P2 |
| 室温力学 | 硬度–回火、抗拉/屈服–硬度、冲击 | P1 |
| 高温力学 | 红硬性（各温度保温 1 h 后硬度）、高温屈服 | P2 |
| 热性能 | 导热（≥3 温度点）、CTE（≥3 温度点）、Ac1/Ac3/Ms | P1 |
| 尺寸稳定性 | 淬火态与各回火温度下的尺寸变化数值 | P1 |
| 淬透性 | 端淬曲线或临界直径 | P2 |

### L4 工艺层

**全部表格化，不用散文。** 散文里查不到"回火 1 小时还是 2 小时"。

```jsonc
{ "type": "table", "title": { "zh": "热处理工艺", "en": "Heat treatment" },
  "tables": [{
    "variant": "proc",                  // 第一列加粗、行距放宽，读起来像工艺卡
    "basis": "spec",
    "cols": [ { "k": "工序", "en": "Operation" }, { "k": "温度", "en": "Temperature", "num": true },
              { "k": "介质 / 冷速", "en": "Medium / cooling" }, { "k": "保温", "en": "Soak" },
              { "k": "目标 / 判定", "en": "Target" } ],
    "rows": [
      { "group": { "zh": "前处理", "en": "Pre-treatment" } },
      [ { "zh": "软化退火", "en": "Soft annealing" }, "816–843 ℃",
        { "zh": "炉冷 ≤11 ℃/h 至 <538 ℃，再空冷", "en": "Furnace cool ≤11 ℃/h below 538 ℃" }, "—", "≤ 200 HB" ],
      [ { "zh": "去应力", "en": "Stress relieving" }, "649–677 ℃", { "zh": "缓冷", "en": "Slow cool" }, "≥ 1 h", { "zh": "粗加工后、精加工前", "en": "After rough machining" } ],
      { "group": { "zh": "硬化", "en": "Hardening" } },
      [ { "zh": "预热", "en": "Pre-heat" }, "649–704 ℃", "—", "—", { "zh": "减小热应力", "en": "Limit thermal stress" } ]
    ]
  }] }
```

`rows` 里放 `{ "group": … }` 对象就是分组行（`colspan` 横跨全表），用来分「前处理 / 硬化 / 回火」，一张表读完整个工艺卡。

必写工序：软化退火、去应力、预热、奥氏体化、淬火（**按截面分档**）、回火（**按用途分档**）、锻造、切削。
高价值但常缺：深冷、磨削与 EDM 白层、焊接。

淬火介质按截面分档（≤63mm 空淬 / 63–150mm 油淬至 538℃ 再空冷 / 更大截面油淬至 65℃）比一句"空冷或油冷"有用得多——后者等于没写。

### L5 供货层

形态 × 尺寸 × 表面 × 公差 × 交货状态（退火 / 预硬 / 淬回火）。

- 尺寸上限要能兑现。写 `Ø8–1000mm` 之前先确认是锻圆还是常规轧材——询价阶段被戳穿一次，后面所有数据都不被信。
- 公差与直线度是采购真正要比的项，缺了只能逐单问。
- 检验选项（超声、探伤、晶粒度、逐支硬度）是差异化卖点，别省。

### L6 依据层｜凭什么信

**旧版 TDS 几乎都缺这一层，而它是最容易出事的一层。**

这一层不用发明字段，用末页一个 `text` 块加一张两列表就够了：

```jsonc
{
  "id": "sp-basis", "layout": "D04", "side": "left",
  "title": { "zh": "数据说明", "en": "Data Notes" },
  "blocks": [
    { "type": "text", "cols": 1, "paras": [
      { "zh": "除标注「标准要求」外，本表数值为典型值，取自常规生产的实测统计，不构成验收依据。验收以合同约定的标准与随货质保书为准。",
        "en": "Values are typical unless marked as specification requirements. They reflect routine production and are not acceptance criteria; acceptance follows the agreed standard and the mill certificate." }
    ]},
    { "type": "table", "tables": [{
      "caption": { "zh": "数据来源与试验方法", "en": "Sources and methods" },
      "basis": "none",
      "cols": [ { "k": "项目", "en": "Item", "w": "26%" }, { "k": "内容", "en": "Detail" } ],
      "rows": [
        [ { "zh": "化学成分", "en": "Chemistry" }, { "zh": "光谱分析（ASTM E415）", "en": "Optical emission, ASTM E415" } ],
        [ { "zh": "硬度", "en": "Hardness" }, "ASTM E18" ],
        [ { "zh": "冲击", "en": "Impact" }, { "zh": "夏比 V 型，10×10 mm，室温", "en": "Charpy V, 10×10 mm, RT" } ],
        [ { "zh": "数据来源", "en": "Source" }, { "zh": "本厂实测 + 标准值汇编", "en": "Mill data and standards" } ],
        [ { "zh": "版本", "en": "Revision" }, { "zh": "V1.0 · 2026-10 · 首版", "en": "V1.0 · 2026-10 · first issue" } ]
      ]
    }]}
  ]
}
```

四件事缺一不可：**数据身份声明、试验方法、数据来源、免责条款**，再加一行版本记录。

技术上再对，缺了这四块，客户拿典型值去验收时企业无据可依。

## 分级：没有就不能发

| 级别 | 内容 |
|---|---|
| **P0** | L0 全部、L1 定义与应用、L2 成分范围、L3 硬度–回火 + 一条力学、L4 退火/淬火/回火、L5 尺寸与表面、L6 四项声明 |
| **P1** | 等效牌号带差异、物理性能完整、热性能、尺寸变化数值、切削性、锻造 |
| **P2** | 淬透性、高温性能、磨削/EDM/焊接、失效模式、同族对照选材 |

P0 缺一项，这份文件不能对外。P2 决定它是"资料"还是"选材工具"。

## 表字段速查

`table` 块里为技术数据加的几个字段，都在 `tables[]` 的每一项上：

| 字段 | 取值 | 作用 |
|---|---|---|
| `basis` | `spec` / `min` / `max` / `typical` / `range` | 表级数据身份，渲染成表题下的徽标 |
| `basis: "none"` | — | 显式豁免：工序表、清单、对策表这类不含验收数值的表用它，validate 不再要求标身份 |
| `cond` | `test_conditions[].id` | 引用试验条件，渲染成表题第二行；引不到 id 会直接报错 |
| `cols[].basis` | 同上 | 列级身份：同一张表里既有标准范围又有典型值时用 |
| `cols[].w` | `"18%"` | 列宽。不指定时浏览器按内容分配，短列常被撑得比长列还宽 |
| `variant` | `"proc"` | 工艺参数表：首列加粗、行距放宽、表头中英分行、长文本可折行 |
| `rows[] = { group: … }` | — | 分组行，`colspan` 横跨全表，把一张大表分成几段 |

`meta.test_conditions` 的每一项：

```jsonc
{ "id": "TC-A",
  "label": { "zh": "淬回火基准", "en": "H&T basis" },
  "items": ["Austenitised 941 °C", "Air cooled", "Tempered 1 h / 25 mm"] }
```

`items` 里的纯 ASCII 文本直接输出（不套语言层），中文才走双语切换——和表格单元格同一套规则。

**跨对开表的列边界要避开折缝**：对开的折缝固定在 210mm（`--page-w`）。十个等分列的边界正好落在折缝上，装订后那一列的文字会被吃掉一截。用 `cols[].w` 微调，让边界落在 200mm 或 220mm 附近。

## 版式映射（D 线）

| 层 | 骨架 | 说明 |
|---|---|---|
| L0 | D00/D01 + 目录右页 `toc_panel` | 文件编号、版本、适用牌号、标准依据 |
| L1 | D04 | 双栏正文；pull-quote 放客户最该记住的一句 |
| L2 | D06 / D07 | 成分横排用 D06 全宽表；成分+等效+供货挤一个对开用 D07 |
| L3 | D06 / D09 / D08b | 性能表 D06；曲线 D08b（矢量图块，必须内联）；硬度-回火是表+曲线一对 |
| L4 | D06 `variant:"proc"` + D08 | 工艺参数表 + 流程示意 |
| L5 | D06 | 供货范围表 |
| L6 | 目录右页 panel + 末页脚注 | 数据身份声明放显眼处，不要塞进页脚 5pt 小字 |

一个对开的容量：全宽表 10–12 行，双列表各 6–8 行，表 + 一条注释。超了就拆对开，别压字号——技术数据表的字号下限比画册高。

## 交稿前自检

- [ ] 每个数值都能回答"这是标准要求、保证值、还是典型值"
- [ ] 所有性能表的试验条件都能追到同一个 `test_conditions` 条目
- [ ] 同一温度、同一硬度在全文出现两次时，数值一致（旧版最常见的翻车点）
- [ ] 硬度不写 `59/61` 这种含义不明的斜杠
- [ ] 冲击功带试验温度与试样尺寸
- [ ] 工艺参数是表，不是段落
- [ ] 标准号带版本年
- [ ] 有版本号、数据基准日、免责条款
- [ ] 尺寸上限是真实供货能力

## 反例（照抄会出事）

| 写法 | 问题 |
|---|---|
| 硬度 `41` 与另一页 `37/40` 并存 | 同一条件两个答案，读者会认为整份文件没校对 |
| "回火每英寸 1 小时，以达到每英寸 2 小时的加热速率" | 句内自相矛盾，热处理厂按哪个执行？ |
| 热性能表条件列写 `atm` | 复制串行，专业读者一眼看出 |
| 把硬度–强度换算曲线放在"典型力学性能"标题下 | 通用换算被误读为该牌号实测 |
| 全篇没有一处"典型值"声明 | 客户拿去验收，纠纷时企业无据 |
| 工艺全用散文 | 现场要的是参数，不是段落 |
